Code quality
that predicts your next outage.

qlint is a multi-language scanner that walks any codebase and produces JSON, HTML, and Markdown reports. Beyond complexity and duplication, it cross-references git history to surface the files most likely to break next.

Install

Two ways to start.

Pick PyPI for a one-shot install, or clone the source if you want to hack.

From PyPI

# latest release
pip install qlint

From source

git clone https://github.com/ropean/qlint.git
cd qlint
pip install -e .

Analysis features

Five signals, one grade.

Every scan combines five independent analyses into a single quality score from 0 to 100. Each signal has its own report section.

Complexity

Cyclomatic complexity

Per-function complexity scores. Anything above 10 is flagged. Top offenders surface in the high-complexity table.

Duplication

Cross-file duplicate blocks

Hash-based 6-line block detection across the whole codebase. Reports total blocks plus duplication percentage.

Security

Secrets & danger zones

Hardcoded credentials, dangerous calls (eval, exec, …), severity-ranked.

Code Smells

Structural smells

Long functions, deep nesting, long parameter lists. Tracked by type so you can see what kind of debt dominates.

Predictive Risk

Files most likely to break

Recency-weighted risk that fuses static metrics with git history — recent churn, bug-fix ratio, author count.

Skill

qlint-refactor for Claude Code

A packaged skill that drives a behavior-preserving refactor loop, using risk_score as the success signal.

Usage

A few flags. A lot of output.

Default scan emits all three formats and auto-opens the HTML. Drop in flags to narrow it down or to dive into the predictive risk view.

Common scans

# scan, write JSON+HTML+Markdown, open HTML
qlint /path/to/repo

# Markdown only
qlint /path/to/repo --format md

# custom HTML output path
qlint /path/to/repo --html report.html

# prompt for path interactively
qlint

Predictive risk

# top 5 narrative on stdout
qlint . --risk

# focus on the last 30 days
qlint . --risk --risk-window 30

# standalone risk markdown file
qlint . --risk-md /tmp/risk.md

Pipe to other tools

# JSON to stdout, no files written
qlint . --json-only | jq '.gitRisk.top_risk_files[0]'

Verbose

# per-file progress, don't auto-open HTML
qlint . -v --no-open

Output formats

Same data, three voices.

Reports default to ~/Downloads/qlint-reports/<repo>-<hash>/report-MMDDYY.{json,html,md} so each run is timestamped and never overwrites the previous one.

JSON

For tooling.

Full structured payload. Pipe through jq, feed into a CI gate, store in a database. Schema is stable and additive.

{
  "qualityScore": 96,
  "grade": "A",
  "gitRisk": {
    "available": true,
    "window_days": 90,
    "top_risk_files": [...]
  }
}
HTML

For humans.

Themed (dark/light), interactive charts, risk-level badges, embedded favicon. Single self-contained file — share by email if you want.

<html data-theme="dark">
  <link rel="icon" type="image/svg+xml"
        href="data:image/svg+xml;base64,…">
  …
</html>
Markdown

For PRs.

Drop into a GitHub issue, Slack snippet, or design doc. Same sections as the HTML report, in plain Markdown tables.

# Code Scanner Report

## Summary
| Metric | Value |
| --- | --- |
| Grade | **A** (96/100) |
| Files | 23 |

How it predicts

Predictive risk, in one formula.

Past fix density is the strongest predictor of future fixes. The score amplifies recent churn × complexity by the share of bug-fix commits and the cost of multi-author coordination.

recent_churn × complexity × (1 + 2·bug_fix_ratio) × (1 + 0.15·authors) / 100

Default window: last 90 days. Bug-fix detection scans commit subjects for fix|bug|hotfix|patch|revert.

recent_churn
Lines added + deleted in the window. Captures activity, not historical bulk.
complexity
Average cyclomatic complexity in the file — proxy for cognitive load.
bug_fix_ratio
Share of recent commits whose subjects look like bug fixes. Doubles its impact.
authors
Distinct contributors. Soft amplifier — coordination cost grows with crowd size.

Claude Code skill

qlint-refactor — close the loop.

A packaged skill that turns the scanner into a feedback signal. The agent picks the riskiest file, proposes a behavior-preserving refactor, re-scans, and verifies the score dropped.

1
Baseline via risk_top.py — the top-N risk JSON.
2
Locate the worst function inside the top-1 file.
3
Propose a minimal, behavior-preserving refactor.
4
Apply, then verify.py against the baseline.
5
Roll back on no-improve. Exit when top-5 are all under 50.

Activates on prompts like

list top risk files explain why this file is risky refactor the risky code reduce risk score run the risk loop
